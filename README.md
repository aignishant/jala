# 🕸️ Jāla

A 152-day computer-networking curriculum that builds a network stack **from the wire up** —
frames, ARP, IPv4, forwarding, routing protocols, TCP, congestion control, DNS, HTTP, TLS,
tunnels — and runs it on a virtual internet made of Linux network namespaces on one laptop.

Nothing under `jala/` is pre-written. Every line is typed from a day document, because you
cannot debug a TCP state machine on Day 100 that you never wrote on Day 61.

## Start here

```bash
./m start 0        # point at Day 0's lesson
./m status         # where we actually are
./m check          # the gate: lint, format, lesson blocks, plan, tests, depth contract
```

Never done this before? Open
[`days/day-000-toolchain-skeleton-driver/LESSON.md`](days/day-000-toolchain-skeleton-driver/LESSON.md).

## 🛑 The rule that comes before every other rule

**Traffic you generate stays inside namespaces you created.** Every scan, flood, spoof,
injection and man-in-the-middle exercise here runs against machines made with `ip netns add`
seconds earlier. The public internet is **read-only and gentle**: `dig`, `traceroute`, `curl`,
a looking glass, a public route collector, at human speed.

Every part that generates traffic names its namespaces. See the plan's §4.2.

## How a day is shaped

A day is a **hub plus one document per subtopic** — never one long page (plan §24):

```
days/day-NNN-<slug>/
├── LESSON.md      # the hub: story · part map · setup · build brief · check · budget · ledger
├── CHECKLIST.md   # the definition of done; ./m done NNN refuses until it is ticked
├── parts/         # THE TEACHING — one document per subtopic
│   └── 01-<slug>/1.1-<slug>.md
└── lab/           # your own scratch code
```

Every part carries a story before any abstraction, a wire-format table when a header is
involved, a topology when it runs in the lab, a line-by-line walkthrough of every code block,
the **real** error text when it breaks, and what changes in a real network. `./m depth`
enforces the half of that a script can check.

## The four lab tiers

| Tier | What it is |
| --- | --- |
| **L0** | one host, user space — codecs, checksums, parsers, state machines |
| **L1** | the virtual lab: `ip netns`, `veth`, bridges, `tc netem`. **Linux only.** |
| **L2** | the public internet, read-only and gentle |
| **L3** | 🅿️ parked — taught as reading, with the arithmetic worked |

L1 needs a Linux kernel. Native Linux, WSL2 on Windows, or a free Linux VM on macOS — macOS
and Windows have no namespace equivalent, and this repository says so rather than pretending.
`./m lab` reports what your machine can host.

## The ledgers

`docs/` is the repository's memory. Seven ledgers are written by hand and append-only —
`PROGRESS`, `PACKAGES`, `SPECS`, `TOPOLOGIES`, `CAPTURES`, `MEASUREMENTS`, `CHANGELOG_PLAN` —
and three are regenerated by `./m tracker` and never edited: `TRACKER`, `CURRICULUM_INDEX`,
`TRACEABILITY`.

Two of those an ordinary project does not have, and they exist for the same reason: six weeks
after a run, the only difference between a result and an anecdote is a row saying which
topology it ran on, what delay and loss were configured, which seed, how many repetitions, and
what the spread was.

**Captures and keys are never committed.** The repository holds what *reproduces* a capture —
never the capture, and never a key.

## Zero budget

No payment, no billing account, no second machine, no network hardware. The whole internet
this curriculum needs fits inside `ip netns` on one laptop.
